## 🎨 方案

### 存量地址修正（核心风险点）

**规范化函数**（放 `reeve-core`，桌面与移动共用；是 reeve 的历史包袱，**不进 crate**）：

```
normalize_legacy_base_url(s):
  s = trim(s)
  空        → 保持 NULL / 空（走官方端点）
  以 # 结尾 → 去掉 #（和随后的末尾 /），其余不动     # 旧语义「锁定不补」= 新规则本来就不补
  去末尾 /
  以 /chat/completions 或 /messages 结尾 → 不动      # 完整端点，crate 同样直通
  末段是 v<纯数字> → 不动
  否则 → 追加 /v1                                     # 旧逻辑会补，修正后行为不变
```

**判据：修正前后，旧逻辑与 crate 拼出的最终请求地址逐字相同。** 用这条写成对照测试：
对一批样例（裸根、带 /v1、智谱 /v4、Gemini `/v1beta/openai`、带 `#`、完整端点、末尾斜杠）
断言 `旧 join_api_path(原值) == crate::join_api_path(normalize(原值))`。

**三个入口都要调用它**：

| 入口 | 做法 |
|---|---|
| 升级 | 桌面 schema **v46**：遍历 `api_profiles` 非空 base_url 逐行修正（事务内，与版本号一起提交）；移动端 schema **v6** 修正 `ai.base_url` |
| 备份恢复 | `mod.rs:3642` 写回 `api_profiles` 时对 base_url 过一遍 |
| 配对导入 | 移动端 `import_api_profile` 收到后过一遍（兼容旧版桌面端） |

**Gemini 已核实（读旧代码）**：旧逻辑确实会把 `/v1beta/openai` 错补成 `/v1beta/openai/v1`，
所以 reeve 的 Gemini 预置带了 `#`（`llm_presets.rs:318`）。用预置建的档案带 `#` → 修正时去掉 `#`，
行为与 crate 一致。只有**手填又没带 `#`** 的 Gemini 档案会被补 `/v1` —— 它在旧版下本来就是 404，
按「前后逐字相同」原则保持原样（不擅自改用户数据的含义），用户点「获取」时 crate 的 404
诊断会给出正确地址。

**另一个要让对照测试盯住的边界**：完整端点但不带版本段（`https://x/chat/completions`）。
旧逻辑拉模型时拼成 `https://x/v1/models`，crate 拼成 `https://x/models` —— 两者不同。
实现时先看对照测试结果，再决定修正函数对这种输入怎么处理（倾向：规范成 `https://x/v1` 形式）。
